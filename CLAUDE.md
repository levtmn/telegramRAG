# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project goal

Local RAG (Retrieval-Augmented Generation) system over Telegram group chat exports. Runs entirely on a Raspberry Pi 5 (aarch64, 4 GB RAM). Multiple chats can be indexed; queries run hybrid search (vector + BM25) with optional metadata filters and reranking.

## Directory layout

```
telegram-{name-or-id}/
    origin/         ← user drops raw Telegram export here (result.json + media dirs)
    processed/      ← generated by preprocess.py: chunks.json + embeddings.pkl (cache)
db/                 ← Qdrant local collection files (shared across all chats)
bm25/               ← serialised BM25 index (pickle)
scripts/
    preprocess.py   ← step 1: parse exports → chunks.json
    index.py        ← step 2: embed chunks → Qdrant + BM25
    query.py        ← step 3: hybrid search + rerank → answer
web/
    app.py          ← FastAPI server (port 8080)
    __init__.py     ← empty, makes web a package
    templates/
        index.html  ← Bootstrap 5.3 chat-style UI
requirements.txt
.env                ← COHERE_API_KEY, ANTHROPIC_API_KEY (gitignored)
```

`result.json` at the repo root is an early test export; production exports go into `telegram-*/origin/`.

## Telegram JSON quirks

Exports may be **truncated** (no closing brackets). Load defensively:

```python
def load_export(path):
    raw = open(path).read()
    last = raw.rfind("\n  }")
    data = json.loads(raw[:last + 4] + "\n ]\n}")
    return data

def get_text(msg):
    t = msg.get("text", "")
    if isinstance(t, list):
        return "".join(e["text"] if isinstance(e, dict) else e for e in t)
    return t
```

Message fields used in this project: `id`, `date`, `from`, `from_id`, `text`, `reply_to_message_id`, `type` (`"message"` | `"service"`).

## Stack choices

| Layer | Choice | Reason |
|---|---|---|
| Vector DB | **Qdrant** (local/embedded mode, no server) | Native hybrid search, sparse+dense, metadata filters; ARM64 wheel available |
| Embeddings | **Cohere `embed-multilingual-v3.0`** (API) | Purpose-built for multilingual retrieval; handles informal/noisy Russian chat text, slang, mixed scripts; `input_type` param separates indexing vs query; no local model needed |
| BM25 | **`rank_bm25`** | Pure Python, zero overhead; catches exact name/date matches that vectors miss |
| Reranker | **Cohere Rerank API** | Best-in-class multilingual reranking; eliminates ~1 GB of local model RAM; free tier sufficient |
| Merging | **RRF** (Reciprocal Rank Fusion) | Parameter-free, robust for dense+sparse fusion |
| LLM | **Claude API** (`claude-sonnet-4-6`) | Answer generation from retrieved chunks |

No `torch` or `sentence-transformers` needed — significantly lighter on RPI5.

## Commands

```bash
# Install dependencies
pip install -r requirements.txt --break-system-packages

# Web interface (access at http://rpi.local:8080)
python3 web/app.py

# CLI — preprocess one chat export
python3 scripts/preprocess.py telegram-mygroup/origin/result.json

# CLI — index all processed chats
python3 scripts/index.py

# CLI — query
python3 scripts/query.py "что писал Вася про машину"
python3 scripts/query.py "ф5 сроки" --author "Таня" --date-from 2025-03-01 --no-llm
```

Always run commands from the project root — `scripts/` and `web/app.py` use relative paths for `db/`, `bm25/`, and `telegram-*/`.

## Web interface

`web/app.py` — FastAPI server, port 8080, accessible on the local network as `http://rpi.local:8080`.

- **Projects modal** — auto-detects every `telegram-*/origin/` directory and shows its status (detected / preprocessed / indexed). One-click indexing with live progress banner.
- **Query panel** — filters by chat and date range (no author filter — LLM-style conversational interface). Streams Claude's answer token-by-token. Sources shown as collapsible chips below the answer.
- **`/api/status`** — returns total chunks, indexed chat count, and `indexing: bool` flag.
- **`/api/projects`** — returns list of all detected projects with status, including `chat_name` read from first chunk.
- **`/api/projects/{name}/index`** — starts background asyncio task, returns `{"started": true}` immediately.
- **`/api/indexing-status`** — poll every 2 s to track indexing progress (`step`, `progress/total`, `message`, `error`, `completed`). Steps: `preprocess → embed → qdrant → bm25 → done`.
- **`/api/query`** — SSE stream (`QueryRequest: {query, date_from, date_to, chat_id}`): embed → vector search → BM25 → RRF → Cohere rerank → Claude stream. Events: `status`, `sources`, `token`, `error`, `done`.

**Chat filter**: the chat dropdown sends `chat_name` (the human-readable Telegram group name, e.g. `"Граница Калининград…"`) as `chat_id`. The backend filters chunks with `c.get("chat_name") == req.chat_id`. Do **not** use the directory name or numeric Telegram ID here — they won't match stored chunks.

Indexing runs as a background asyncio task. The frontend polls `/api/indexing-status` every 2 seconds and shows a progress banner. On completion: Bootstrap toast + Web Notifications API + optional ntfy.sh push (set `NTFY_TOPIC=your-topic` in `.env`).

Embedding results are cached per project in `telegram-*/processed/embeddings.pkl`. Re-indexing after adding a new chat only embeds that chat's chunks — all others load from cache instantly. First full index of ~11 k chunks takes ~50–60 min due to Cohere rate limits; subsequent re-indexes are instant.

To add a new chat: create `telegram-{name}/origin/`, drop `result.json` inside, refresh the Projects modal, click Index.

## Chunking strategy

Chunks are conversation threads, not sliding windows:
1. Build a reply-graph from `reply_to_message_id` links → connected components = threads.
2. Within a thread, also group by 30-minute gaps (fallback for unreplied messages).
3. Target 300–600 tokens per chunk; split long threads at natural gaps.
4. Each chunk stores a header in the text for BM25: `[Чат: {chat_name} | Дата: {date} | Авторы: {authors}]\n{messages}`.

Metadata stored per chunk in Qdrant payload: `chat_id`, `chat_name`, `date_start`, `date_end`, `authors` (list), `message_ids` (list).

## Hybrid search pipeline

```
query
  ├─ Cohere dense vector (top-20) ─┐
  └─ BM25 keyword (top-20)        ─┴─ RRF merge → optional date/author filter
                                                │
                                      Cohere Rerank (top-5)
                                                │
                                     Claude streaming answer
```

## Chat history

Conversation history is persisted in **`data/history.db`** (SQLite, stdlib `sqlite3`, gitignored).

Schema: `sessions(id, title, created_at)` + `messages(id, session_id, role, content, sources, created_at)`.

Each query/response pair is saved automatically after the Claude stream completes. The `session_id` (UUID) is generated by the browser on page load and sent with every `/api/query` request.

History API:
- `GET /api/history` — list sessions (last 100, newest first)
- `GET /api/history/{id}` — full session with messages; `sources` field is pre-parsed JSON array
- `DELETE /api/history` — clear all
- `DELETE /api/history/{id}` — delete one session

UI: clock-history icon in navbar opens a Bootstrap Offcanvas sidebar. "Новый" button starts a fresh session. "Очистить" clears all history. "PDF" calls `window.print()` — `@media print` CSS hides nav/filter/input and renders the chat as a printable/PDF document.

## Projects — display name, date range, archive upload

Each project directory can have a `telegram-{name}/metadata.json`:
```json
{ "display_name": "Human-readable name", "created_at": "2026-05-26" }
```

`scan_projects()` reads this; `display_name` falls back to `chat_name` from chunks, then to the directory slug.

`PATCH /api/projects/{name}/metadata` — update display name (pencil icon in Projects modal).

`POST /api/projects/upload` — multipart form (`file`: `.zip` or `.tar.gz`, `display_name`: optional). Extracts `result.json` from archive root (or one level deep), creates `telegram-{slug}/origin/result.json`, writes `metadata.json`. Requires `python-multipart`.

Date range: `scan_projects()` computes `date_min`/`date_max` from all `date_start`/`date_end` fields in chunks. Shown in Projects modal. Selecting a specific chat in the filter dropdown auto-fills the date range inputs and opens the filter bar.

## Landing page and auto-start (deploy/)

`deploy/` contains deployment files for running on the RPi as a persistent service:

- `telegram-rag.service` — systemd unit; runs `web/app.py` on boot, restarts on failure
- `nginx-telegram-rag.conf` — nginx serves the landing page at port 80 (`http://rpi.local/`); root is `/var/www/telegram-rag`, **not** the project dir (see below)
- `README.md` — 2-step setup instructions

**nginx cannot serve from `/home/user/...`**: the worker runs as `www-data`, and `/home/user` is mode `0700`, so any root under it 404s with `stat() … Permission denied`. Deploy copies `web/landing.html` → `/var/www/telegram-rag/landing.html` (owned by `www-data`). After editing the source `web/landing.html`, re-copy it there.

`web/landing.html` — static page (served by nginx, no Python needed). Checks service health via `fetch('http://rpi.local:8080/api/status')` every 5 s, shows status dot and chunk count, enables "Открыть" button when service is up.

The FastAPI app has `CORSMiddleware(allow_origins=["*"])` so the landing page can call the API cross-origin (port 80 → 8080).

## Known gotchas

- **Qdrant v1.18+**: `QdrantClient.search()` was removed. Use `client.query_points(collection_name=…, query=vec, limit=n)` and access results via `results.points` (each item has `.payload`, `.score`).
- **Chat filter mismatch**: chunks store `chat_name` (the Telegram group display name). Always filter on that field — not the directory name and not the numeric `chat_id` from the export. See `scan_projects()` in `web/app.py` which reads `chat_name` from `chunks[0]`.
- **Secure-context browser APIs over plain HTTP**: the app is served over `http://rpi.local:8080` (not HTTPS, not `localhost`), which is **not a secure context**. APIs like `crypto.randomUUID()` and `crypto.subtle` are `undefined` there and throw — and because the UI is one big inline `<script>`, a throw at the top (e.g. session-id init) aborts the *entire* script, so nothing loads (empty chat dropdown, projects stuck spinning). It works on `localhost` (treated as secure), which masks the bug in dev. Use `crypto.getRandomValues` (available in non-secure contexts) — see `genUUID()` in `index.html`. Avoid secure-context-only APIs in this UI.
- **Cohere rate limits on first index**: trial tier is 100k tokens/min. With ~11 k chunks at ~400 tokens each, full indexing takes ~50–60 min. The `_embed_texts()` function paces with `max(1.0, batch_tokens / 1350)` sleep and retries on 429 after 65 s.

## Notes

- `qdrant-client` and `rank_bm25` have ARM64 wheels; no compilation needed.
- Cohere free tier: 1,000 embed calls/minute, 100 rerank calls/minute — sufficient for this data volume.
- Keep Cohere embed batch size at 96 (API max) to minimise round-trips during indexing.
- Store `COHERE_API_KEY` and `ANTHROPIC_API_KEY` in a `.env` file; load with `python-dotenv`.
- The `.claude/settings.local.json` permits `Bash(python3 *)` without prompts.
